# 分类规则引擎

分类准不准，决定了账单有没有用。这一页说明规则怎么工作、怎么加。

## 一条规则 = 条件 + 动作

**条件**（可以只写其中一个，也可以组合，全部满足才算命中）：

| 条件 | 说明 |
| --- | --- |
| 关键词 | 可写多个，用逗号分隔，命中其一即可（如 `滴滴,花小猪,高德打车`） |
| 匹配范围 | 任一字段 / 交易对方 / 商品说明 / 交易分类 / 支付方式 |
| 金额区间 | 如「5 元以内」，写成最小 0 / 最大 5 |
| 时间段 | 如 `11:00`–`14:00`，支持跨零点（`21:30`–`05:00` 算夜宵） |
| 方向 | 只看支出 / 只看收入 / 只看不计收支 |
| 来源 | 只对某个渠道生效（支付宝 / 微信 / 银行 / 手工） |
| 支付方式 | 如只匹配「零钱」「花呗」 |
| 完全匹配 | 勾选后要求商户名完全相等，而不是包含 |

**动作**（四选一）：

| 动作 | 效果 |
| --- | --- |
| 归到某个分类 | 填分类 / 子分类，最常见的用法 |
| 标记为不计收支 | 转账、还款、理财进出，不进收支统计 |
| 忽略，不入账 | 这条流水直接不要（如刷单、测试转账） |
| 只打标签 | 不动分类，只加标签（如「小额」「大额」），可以和多条叠加 |

## 匹配顺序

按**优先级**从小到大判断，**先命中的那条生效**；打标签的规则不参与这个竞争，会全部叠加。

所以写规则的口诀和 double-entry-generator 的建议一样：**从宽泛到具体**

```
优先级 5–20    具体商户       滴滴 → 交通/打车
优先级 45      时段兜底       餐饮 + 11:00–14:30 → 餐饮/午餐
优先级 50      宽泛类别       含「餐饮」→ 餐饮
优先级 90+     最后兜底
```

内置的时段规则就是靠这个顺序工作的：`肯德基 12:15` 先被「肯德基 → 快餐」（优先级 15）命中，
所以是**快餐**而不是午餐；而一个没见过的餐馆在 12:30 消费，会落到「餐饮 + 午餐时段」（优先级 45）。

## 内置了什么

- **287 条中文商户规则**：肯德基、瑞幸、美团外卖、滴滴、淘宝、永辉、国家电网、腾讯视频……
- **6 条条件规则**：
  - 餐饮按用餐时段细分：早餐 / 午餐 / 晚餐 / 夜宵
  - 5 元以内打「小额」标签 —— 月末能看清零钱都花哪了
  - 1000 元以上打「大额」标签 —— 方便回看
- **内部资金流转识别**：转账、信用卡还款、余额宝、零钱通、提现、理财、已关闭订单，自动记为「不计收支」，不虚增消费

内置规则会在版本升级时自动重建，**你自己加的规则不受影响**。

## 怎么加

设置 → 分类规则 → 新增。填完可以直接点「试算」：写一条流水的样子（商户、金额、时间），
它会告诉你命中哪条规则、最终归到哪个分类——不用真的记账来试。

两个更省事的办法：

1. **改一笔的的分类**：在流水里点任意一笔，改分类保存。系统会把「商户 → 分类」记成一条规则（优先级 5，最优先），下次自动归类。
2. **按商户批量改**：统计 → 常去的商户 → 点一个商户 → 选分类，会一次性改掉它的全部流水，并生成规则。

## 没认出来的交易怎么办

通知里没有金额、或者格式不认识的，不会丢，会进**待录入**队列（首页会给提示）。
点开能看到通知原文，补上金额和商户就正式入账，并且顺手把这个商户记住。
银行通知模板千奇百怪，这一步是兜底的关键。

## 参考的开源项目

做这一版时对照了三个同类项目：

| 项目 | 借鉴的点 |
| --- | --- |
| [deb-sig/double-entry-generator](https://github.com/deb-sig/double-entry-generator) | 条件式规则的设计：peer / item / category / method / 时间区间 / 金额区间 / fullMatch / ignore，以及「从宽泛到具体」的排序建议 |
| [FridayKoi/WhereIsMyMoney](https://github.com/FridayKoi/WhereIsMyMoney) | 未识别交易进「待录入」队列、收款方维度的统计与批量操作 |
| [mohan-246/Spenz](https://github.com/mohan-246/Spenz) | 商户规则表里带「排除出支出」的标记（对应本项目的「不计收支 / 忽略」动作） |

另外通知抓取的整体思路（NotificationListenerService + 文本解析）与
[pppscn/SmsForwarder](https://github.com/pppscn/SmsForwarder) 一致。
