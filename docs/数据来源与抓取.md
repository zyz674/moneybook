# 数据来源与抓取配置

## 0. 先明确边界（很重要）

| 想法 | 可行性 | 原因 |
| --- | --- | --- |
| 直接读微信/支付宝的本地数据库 | ❌ | Android/iOS 应用沙箱隔离，第三方 App 无权访问；root/越狱后也常被加密，且有封号与合规风险 |
| 调用官方接口拉个人流水 | ❌ | 微信支付、支付宝的账单 API 只对**商户**开放，拿到的是「你作为商家收款」的数据，不是你的个人消费流水 |
| 读通知栏 | ✅ Android | 系统提供的 NotificationListenerService，用户显式授权即可，无需 root |
| 读官方导出的账单文件 | ✅ 全平台 | 支付宝/微信官方都支持导出 CSV，数据最准，只是要手动导出 |
| 截图 OCR / 短信 | ✅ 半自动 | iOS 快捷指令可从截图取文本；安卓短信转发器可转发银行短信 |

结论：**最靠谱的组合是「通知实时抓 + 官方账单定期校准」**，本工具两条通道都支持，并且会自动去重合并。

## 1. 通道 A：Android 通知监听

原理：微信/支付宝在付款成功时会发一条通知，通知文本里通常带金额和商户，例如
`微信支付：已支付¥35.80，收款方美团外卖`。用通知监听拿到文本后 POST 到本工具即可。

### 方式 1：MacroDroid（零代码，推荐先试）

1. 应用商店安装 **MacroDroid**（免费版够用，需授予「通知访问权限」）
2. 新建宏：
   - **触发器**：通知 → 收到通知 → 选择应用「微信」和「支付宝」（可建两个宏）
   - **动作**：网络 → HTTP 请求
     - 方式：`POST`
     - URL：`http://192.168.1.100:8787/api/ingest`（换成你启动时打印的地址；设了口令就加 `?token=你的口令`）
     - Content-Type：`application/json`
     - Body：从右侧「魔法文本/变量」里插入通知的**标题**、**内容**、**应用包名**，拼成：
       `{"text": "[通知标题] [通知内容]", "package": "[应用包名]"}`
3. 保存并启用。之后每笔支付都会实时进账。

> 变量名各版本略有差异，用界面上的插入按钮选，不要手敲。
> 若服务端设了口令，记得在 URL 后面带上 `?token=xxx`。

### 方式 2：Tasker / Automate

同样思路，触发条件选「通知」，动作选「HTTP Request」。Tasker 需要 AutoNotification 插件读通知内容。

### 方式 3：短信转发器（开源，专治银行短信）

用 [SmsForwarder](https://github.com/pppscn/SmsForwarder)：
- 转发方式选 **Webhook**
- 服务器地址：`http://192.168.1.100:8787/api/ingest`
- 请求体（JSON）：把短信内容变量塞进 `text` 字段即可

### 方式 4：自己写一个抓取 App

见 `android/` 目录，里面有一份完整的最小实现（Kotlin，约 120 行，无第三方依赖），
用 Android Studio 打开即可编译安装。核心就是一个 NotificationListenerService，
把 `onNotificationPosted` 收到的文本 POST 出去。

### 接口约定

```http
POST /api/ingest
Content-Type: application/json      （也支持 text/plain 直接发原文，方便快捷指令）

{
  "text": "微信支付：已支付¥35.80，收款方美团外卖",   // 必填，通知/短信原文
  "source": "wechat",        // 可选：alipay / wechat / bank，不填自动判断
  "ts": "2026-09-12 12:31:10",  // 可选：不填用服务器当前时间
  "package": "com.tencent.mm",  // 可选：用于判断来源
  "device": "我的手机"           // 可选：标记设备
}
```

返回：

```json
{"ok": true, "saved": 1, "total": 1, "results": [
  {"ok": true, "status": "new", "id": 42,
   "record": {"ts": "2026-09-12 12:31:10", "amount": "35.80", "direction": "out",
              "counterparty": "美团外卖", "category": "餐饮", "source": "wechat"}}]}
```

`status` 含义：`new` 新记账；`dup` 与已有记录重复（未新增）；`merged` 合并进了相近的一笔（并用新信息补全）。

## 2. 通道 B：官方账单文件投递（最准）

### 导出方式

- **支付宝**：我的 → 账单 → 右上「…」→ 开具交易流水证明 → 用于个人对账 → 填邮箱 → 收到 zip/CSV（GBK 编码）
- **微信**：我 → 服务 → 钱包 → 账单 → 右上「常见问题」→ 下载账单 → 用于个人对账 → 收到 zip/CSV（UTF-8 BOM）

### 投递方式（任选）

1. **丢文件**：把 CSV/zip 复制到 `data/inbox/` 目录，每 3 小时（或点界面「同步」）自动导入，导入后自动移入 `data/inbox/done/`
2. **手机上传**：手机打开记账本 → 「我的」→ 数据导入 → 选文件（服务端自动识别 GBK / UTF-8，不用手动转码）
3. **远端拉取**：`config.json` 里 `sync.pull_urls` 填网盘直链，随同步周期自动下载导入：
   ```json
   "sync": { "pull_urls": [{"name": "alipay-2026-09.csv", "url": "https://example.com/xxx.csv"}] }
   ```

### 去重规则（不会记两遍）

1. 有官方单号（交易单号/交易订单号）→ 按单号唯一
2. 没有单号 → 按「来源 + 分钟 + 金额 + 方向 + 商户」指纹
3. 通知先到、账单后到 → 按「同来源 + 同金额 + 同方向 + 时间相差 ≤ 20 分钟 + 商户名相近」判定为同一笔，
   自动合并并用账单里的官方信息补全单号（商户名明显不同则视为两笔，不会误合并）
4. 同一个文件重复导入 → 文件指纹识别，直接跳过

## 3. 通道 C：iOS 快捷指令（iPhone 兜底）

iPhone 无法后台读别的 App，但可以用「快捷指令 + 个人自动化」做到接近自动：

**做法一：手动一键记账**
1. 快捷指令 App → 新建快捷指令
2. 动作：`要求输入`（输入类型：文本）→ `获取 URL 内容`
   - URL：`http://192.168.1.100:8787/api/ingest?token=你的口令`
   - 方法：POST，请求体：JSON，字段 `text` = 上一步的输入
3. 把它加到主屏幕或「辅助功能 → 轻点背面」，付款后一键发送

**做法二：截图 OCR**
1. 付款后截图
2. 快捷指令：`从图像中提取文本`（选最近截图）→ `获取 URL 内容` POST 到 `/api/ingest`
3. 可以做成「个人自动化 → App 关闭时（微信/支付宝）触发」

**做法三：只读不写**
每天 12 点用快捷指令 GET `/api/report/preview`，把返回文本用「显示通知」弹出来，
这样不配推送通道也能在 iPhone 上看到每日账单。

## 4. 提示词规范：怎么写都行

解析器对常见写法都能认，例如：

- `微信支付：已支付¥35.80，收款方美团外卖`
- `支付宝支付成功，付款金额12.50元，商户：肯德基`
- `微信支付收款到账通知：微信转账收款 ￥100.00`
- `【招商银行】您尾号1234的储蓄卡09月12日12:30向某某超市支付人民币128.40元，余额5000.00元。`

判定规则：
- 金额：优先取 `¥/￥` 后面的数字，其次取 `金额/人民币/消费/支付…` 附近带「元」的数字
- 方向：支出/消费/付款/支付/扣款 → 支出；收入/收款/到账/退款/收到 → 收入
- 转账、信用卡还款、余额宝、零钱通、提现、理财 → **不计收支**（避免把搬钱当成消费）
- 验证码、登录、优惠券、活动等噪音通知直接丢弃，并记一条「拒绝日志」（「我的 → 最近任务」可查）

如果某条通知解析失败，把原文发我，加一条规则就行。
